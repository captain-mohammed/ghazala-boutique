# بوتيك غزالة — GHAZALA BOUTIQUE

**أناقة تمشي بخطى واثقة** — نظام إدارة المخزون والمبيعات مصمم خصيصاً لبوتيك غزالة.

تطبيق PWA يعمل **بدون إنترنت 100%** على هاتف أندرويد. كل البيانات تبقى في جهازك.

**التطبيق المباشر:** https://captain-mohammed.github.io/ghazala-boutique/

![Ghazala Boutique](readme-header.png)

## المميزات

- 🔒 **قفل برقم سري** — يُعيَّن عند أول فتح، مشفّر (SHA-256)، لوحة مفاتيح زجاجية
- 🏠 **لوحة رئيسية حيّة** — عدّاد أرقام ميكانيكي متحرك، شريط ضوئي ذهبي، تنبيهات نقص ونفاد ورکود
- 👠 **المخزون** — إضافة موديلات بسرعة (كود تلقائي GHZ-0001) وبعدة مقاسات بضغطة، فاتورة وارد بالجملة مع اسم المورد، قوة المقاسات، بحث وفلاتر، سجل حركات لكل موديل
- 🛍️ **بيع سريع** — سلة عائمة ذكية لا تضيع بإعادة الفتح، فلاتر فاخرة، FAB للمسح والبيع من رسالة، مسح باركود شركة التوصيل عند الدفع، أجور توصيل تلقائية (5,000 د.ع افتراضياً)
- 💬 **رسالة واتساب جاهزة** — تُفتح واتساب مباشرة برقم الزبون والرسالة مكتوبة كاملة، والنص قابل للتخصيص من الإعدادات
- 📋 **سجل المبيعات** — تبويب مستقل في الشريط السفلي، حالات (قيد التوصيل / تم التسليم / راجع)، الإرجاع يعيد الكميات للمخزون تلقائياً
- 📊 **تقارير** — اليوم/أسبوع/شهر، الأكثر مبيعاً، الربح حسب النوع، نسبة التصريف، مخزون راكد، رسم بياني لآخر 14 يوم، ودفتر إقفال الشهر
- ✅ **الجرد** — عدّ فعلي مع تطبيق الفروقات بسجل كامل
- 💾 **نسخ احتياطي** — JSON كامل + تصدير Excel، مع تذكير أسبوعي
- 🕐 **توقيت بغداد** — كل الساعات وبداية «اليوم» بتوقيت بغداد (UTC+3)، عرض 12 ساعة ص/م
- 🎨 **ثيم زجاجي** بهوية بوتيك غزالة (نبيتي/ذهبي/عاجي) مع وضع ليلي «ليل الغزالة» تلقائي بتوقيت بغداد، حركات تفاعلية واعية لموضع اللمس، شعار قابل للتغيير من داخل التطبيق

## التشغيل

```bash
npm install
npm run dev       # تطوير
npm run build     # نسخة الإنتاج في dist/
npm run preview   # معاينة النسخة النهائية
```

## تثبيته على الهاتف

1. افتح الرابط في **Chrome** على هاتف أندرويد: https://captain-mohammed.github.io/ghazala-boutique/
2. قائمة Chrome ⋮ ← **إضافة إلى الشاشة الرئيسية**
3. انتهى — التطبيق سيعمل بدون إنترنت من بعدها

كل `push` إلى `main` يُبنى ويُنشر تلقائياً عبر GitHub Actions — اسحب للأسفل داخل التطبيق (أو أعد فتحه) ليظهر إشعار التحديث.

## النسخ الاحتياطي

من التطبيق: **المزيد ← النسخ الاحتياطي** — خذ نسخة JSON أسبوعياً (تذكير تلقائي مدمج).
مسح بيانات المتصفح يمسح قاعدة البيانات — النسخة الاحتياطية هي الحماية الوحيدة.

# سجل الإصدارات — CHANGELOG

**Versioning scheme:** `MAJOR.MINOR.PATCH` — during active development the app moves through **0.1.0 → 0.1.9**, then rolls to **0.2.0**, then 0.2.1…0.2.9 → **0.3.0**, and so on. Bumping the minor digit (0.1→0.2) happens when a batch of new features is complete and stable; small improvements within a batch raise the patch digit. **1.0.0** is reserved for the first stable release used in the shop day-to-day.

Each version below lists **what was added and why it matters to the shop**.

## [0.15.2] — 2026-09-12 — الإعدادات حيّة في كل مكان

### Fixed
- **إعدادات الرئيسية كانت لا تُحمَّل أصلاً** — جولة تدقيق شاملة لكل قيمة تأتي من الإعدادات كشفت أن الرئيسية فقدت تحميل الإعدادات كلياً في إعادة هيكلة قديمة، فكانت: **«المدينة القديمة»** تبقى فارغة دائماً، وتنبيه **الرکود** لا يظهر أبداً، وحلقة **الهدف اليومي** تتجاهل الهدف المختار، وميدالية **صحة النسخة** تظل «لا نسخة بعد» حتى بعد أخذ نسخة. الآن تُجلب الإعدادات مع كل دورة تحديث (4 ثوانٍ) — الأربع عادت كلها، وأي تغيير في الإعدادات ينعكس دون مغادرة الصفحة. *مُختبر حياً: القيم كُتبت مباشرة في قاعدة البيانات والصفحة تغيرت وحدها في الاتجاهين.*
- **حد الرکود في التقارير حيّ** — كان يُقرأ مرة عند فتح الصفحة؛ الآن يُجلب مع كل دورة (5 ثوانٍ): رفع الحد إلى 45 يوماً أخفى بطاقة الراکد وحدها دون مغادرة.
- **دفتر الموردين حيّ** — كان يُحمَّل مرة واحدة عند الفتح؛ الآن يتبع النمط القياسي (5 ثوانٍ) — بيع جديد أو مورد سُجّل يظهران دون مغادرة، وبوابة التحميل تظهر على أول جلب فقط بلا رمش.

### Verified (القيم التي كانت سليمة وثُبِّت حيّايتها)
- أجور التوصيل وشركات التوصيل في إتمام البيع: تُقرأ عند كل فتح للإتمام ✓ — وحساب الشركات يجلبها كل 4 ثوانٍ ✓
- قالب رسالة الواتساب في السجل: يُجلب كل 4 ثوانٍ ✓
- هدف الخزنة: يُقرأ مع كل تحديث للخزنة على الرئيسية ✓
- الموردون في نموذج إضافة الموديل وفاتورة الوارد: يُقرأون عند كل فتح للورقة ✓
- الرقم السري: يُقرأ عند كل محاولة دخول ✓

## [0.15.1] — 2026-09-12 — لمسات دُرّبة الغزالة

### Added
- **🥿 دُرّبة الغزالة (fly-to-cart)** — لمسة «+» في البيع لم تعد مجرد رقم يعلو: رقاقة دائرية بصورة القطعة نفسها تطير من البطاقة بقوس ذهبي حتى شارة السلة، خلفها خطوات حوافر ذهبية باهتة، والشارة تمسكها بانضباط زنبركي وتومض. نصف ثانية بالضبط، وتحترم `prefers-reduced-motion` (تُعوَّض بنبضة الشارة وحدها). *الفائدة: القطعة تغادر الرف وتحطّ في السلة أمام عينك — هوية «دفتر الحركة السريعة» كلها في لمسة واحدة.*
- **💓 نبض السلة** — شارة السلة تتنفس نبذة ذهبية هادئة كل ثانيتين ونصف ما دامت فيها قطع — السلة شيء حي ينتظر، لا رقم ميت. وإذا نُسيت سلة ممتلئة 20 دقيقة نادتك **مرة واحدة**: رجّة لطيفة للشريط + اهتزاز + «سلتك ما زالت بانتظارك 🛍» — ولا إلحاح بعدها حتى تُفرَّغ السلة وتبدأ أخرى.
- **👣 خُطوة** — نبض اللمس عند كل إضافة يقوى تدريجياً مع امتلاء السلة (من 6 إلى 10 م.ث) — يدك «تحس» باليوم وهو يكبر قطعة وراء قطعة.

## [0.15.0] — 2026-09-12 — وقت الوصول يُختار

### Added
- **🕐 وقت الوصول للرف** — نموذج إضافة الموديل في المخزون صار يحمل حقل «وقت الوصول»: يبدأ «الآن» بتوقيت بغداد، ويُعدَّل ليوم وساعة وصول البضاعة الحقيقيين (منتقي تاريخ ووقت + زر «الآن» يعيدها للحظة الحالية). أي وقت مستقبلي يُرفض فوراً ويرجع «الآن». وفي تعديل الموديل يظهر الحقل معبّأً بأقدم لحظة وصول بين قطعه، والحفظ يطبّقها على كل قطعه. *الفائدة: البضاعة اللي وصلت من ثلاثة أيام تُسجَّل اليوم — لكن التطبيق يحسبها من يوم وصولها الفعلي، لا من يوم كتابتها.*

### Changed
- **كل التطبيق يحترم وقت الوصول المعدّل** — ترتيب «الأحدث» في المخزون والبيع، ساعة الرکود (الرئيسية والتقارير واقتراحات غزالة)، دفتر إقفال الشهر («الموديلات التي وصلت»)، دفتر الموردين، سجل حركات القطعة (حركة الإضافة الأولية تحمل تاريخ الوصول نفسه)، والنسخ الاحتياطي وتصدير الإكسل — كلها تحسب من اللحظة المختارة.

### Internal
- `addProduct` يقبل `createdAt` مخصصاً (يُتجاهل إن كان مستقبلياً)، و`logMovement` يقبل تاريخاً صريحاً؛ ومساعدا توقيت بغداد الجديدان `baghdadLocalInput` / `isoFromBaghdadLocal` يحوّلان بين حقل التاريخ واللحظة الحقيقية — محاكة توقيت بغداد تُقاس عند كل تحويل فلا تتأثر بأي تغيير مستقبلي للتوقيت الصيفي.

## [0.14.0] — 2026-09-12 — دفتر الزبونات: الكل يعرف نفسه

### Added
- **📇 دفتر الزبونات** — صفحة جديدة في «المزيد» تحت عنوان الزبونات: كل زبونة تُجمع **تلقائياً** من مبيعاتها وحجوزاتها ومناسباتها — بلا إدخال يدوي. لكل زبونة: إجمالي مشترياتها، عدد العمليات والقطع، آخر زيارة، بحث بالاسم أو الرقم، وشارات ذكية — **VIP** بإطار ذهبي (150 ألف أو 3 عمليات)، شارة **حجز** ما دام حجزها قائماً، و**🎂 عدّاد أيام** للمناسبة القريبة خلال أسبوعين. وبالضغط: بطاقتها كاملة بإحصائياتها، وزر واتساب، وسجل عملياتها بتواريخها ومبالغها. *الفائدة: تعرفين زبوناتك الأثمن من نظرة، وتحچين مع كل وحدة لغة ولاء.*

### Internal
- تجميع الزبونات يوحّد الاسم والرقم من الجداول الثلاثة (مبيعات، حجوزات، مناسبات) — صفر تغيير على قاعدة البيانات.

## [0.13.0] — 2026-09-12 — بطاقة ثابتة مهما كثر المحتوى، ودفتر الموردين

### Added
- **🏪 دفتر الموردين** — صفحة جديدة في «المزيد»: لكل مورد كم موديل وقطعة اشتريتِ، بكلفة إجمالية، وكم بيع منها وإيراده وربحه الصافي، وكم بقي على الرف، ونسبة التصريف (المبيع ÷ المشتراة) بشريط ذهبي، مع قائمة موديلاته بصورها وأسعارها. الأسماء تأتي من سجل الموردين، وتوسّع أي بطاقة يعرض كل الأرقام. *الفائدة: تعرفين منين ينبغى الشراء أكثر ومنين ما يستحق.*

### Changed
- **بطاقة المخزون ثابتة الحجم نهائياً** — الصورة مربعة، وتحتها «النوع» بعرض البطاقة كاملاً، ثم صف واحد: القياسات المتوفرة يميناً في حاوية خاصة بها (شبكة عمودين، بلا إطار ظاهر) ودوائر الألوان يساراً (عمودان، صفّان كحد أقصى، بلا أي خلفية). البطاقة لا تتمدد مهما كثرت الألوان أو المقاسات — الزيادة تُقتصد بنظافة.

### Fixed
- **تسميات الإتمام لم تعد تتحرك أثناء التمرير** — لمس أي مكان في الورقة كان يبدأ سحبها للإغلاق فتتزحزح النموذج مع الإصبع ويرتد. الآن السحب للإغلاق من مقبض الورقة ورأسها فقط — تمرير النموذج تمرير صافٍ بلا اهتزاز.

## [0.12.3] — 2026-09-12 — شجرة النوع تفهم أبوابها، وكل موديل يحمل سلسلتها

### Fixed
- **فلاتر النوع تحترم الأبواب** — كانت القائمة الفرعية «↳ كعب عالي» تحت «بوت» تلقط كل قطعة اسم تفصيلها «كعب عالي» حتى لو نوعها الرئيسي مختلف (العدد كان يكذب). الآن كل مستوى يُحسب ويُطابق **داخله أبويه فقط** — جرّبنا حالة التعارض حرفياً: ↳ كعب عالي تحت بوت أظهرت قطعة بوت فقط، والنوع الرئيسي كعب عالي أظهر قطعيه هو.
- **كل موديل يحمل سلسلته كاملة** — بطاقة البيع والبطاقات الأخرى كانت تعرض نوع القطعة الأولى فقط؛ الآن السلسلة تُجمع من **كل قطع الموديل** (بوت - كعب عالي)، وبطاقة المخزون كذلك.
- **ترحيل آمن للبيانات القديمة** — موديلات سُجلت قبل شجرة النوع واسمها يحمل التفصيل (مثل «بوت كعب عالي أسود») صارت تُكتمل شجرتها تلقائياً عند أول تشغيل — نملأ المستويات الفارغة فقط، ولا نمسح ما اخترتِه يدوياً.
- **التفصيل يظهر في كل مكان** — صفحة تفاصيل القطعة، الجرد، البيع من رسالة، رسائل الواتساب (سطر القطعة يحمل سلسلة النوع بدل الاسم الداخلي)، وطلبات إعادة التعبئة تحمل الشجرة كاملة.

## [0.12.2] — 2026-09-12 — المورد والتوصيل جاهزان مسبقاً، ونسبة التصريف بفترتك

### Changed
- **شركة التوصيل تُختار مسبقاً** — عند فتح الإتمام تكون أول شركة من حساب الشركات محددة جاهزة (لا «بدون» فارغة). إن لم تُسجلي شركات بعد، يقولك الحقل بلطف لتضيفيها أولاً من الإعدادات.
- **المورد يُختار مسبقاً** — في إضافة موديل وفاتورة الوارد: أول مورد مسجل يظهر محدداً من البداية، وإن لا يوجد موردون يقودك الحقل إلى إضافتهم من الإعدادات. لا خيارات «بدون» بعد اليوم.
- **نسبة التصريف بفترة تختارينها** — شرائح فترة (اليوم / 7 أيام / 30 يوم / الكل) فوق بطاقة نسبة التصريف في التقارير، والنسبة تُحسب من مبيعات الفترة المختارة ضد المخزون الحالي — وبنفس الفترة تُحسب بقي بقية بطاقات التقارير (الإيراد، الربح، الأكثر مبيعاً، حركة الرکود).

## [0.12.1] — 2026-09-12 — الإتمام يفهم الألوان، والقوائم تثبت تحت حقولها

- **المقاسات تتبع اللون حصراً** — تغيير اللون في إتمام البيع لم يعد يخلط مقاسات الألوان الأخرى؛ قائمة المقاسات تعرض مقاسات اللون المختار فقط بكمياته المتاحة، والسطر كله يبقى داخل اللون المختار.
- **قائمة الاختيار تحت الحقل تماماً** — ورقة Pick كانت تُقاس قبل استقرار حركة فتح الورقة فتنزلق عن مكانها؛ الآن تُثبَّت بعد استقرار الحركة، وتفتح قائمة واحدة في كل التطبيق (فتح قائمة يغلق أختها)، وتُرسم خارج أوراق التمويه فلا تُقصّ.
- **بطاقة البيع تعرض كل الألوان** — بدل لون واحد، تظهر كل ألوان الموديل بدوائرها مع كمية كل لون تحتها.
- **المورد إجباري في إضافة الموديل** — لا حفظ دون تحديد المورد، مع تحذير بصري حتى يُستكمل.
- **تفصيلات النوع إجبارية** — إذا عرّفتِ قائمة فرعية للنوع في الإعدادات صار اختيار منها شرطاً للحفظ مثل النوع نفسه.
- **أزرار + و − تتوسّط** — الرقم كان يرتد عن مركز الزر؛ الآن محاذاته مضمونة في كل السلات.

## [0.12.0] — 2026-09-12 — قوائم اختيار بشخصية غزالة

- **وداعاً للقوائم المنسدلة الأصلية** — كل قائمة اختيار في التطبيق (المحافظات، شركة التوصيل، الموردون، الشهر، ألوان ومقاسات سلة البيع) صارت مكوّن «Pick» الجديد: الشريحة الذهبية تنفتح الورقة من مكان الحقل نفسه، والخيارات تدخل واحداً تلو الآخر، ووميض ذهبي يجري على الخيار المختار باستمرار، وعند الاختيار يقلب مجسم الحقل لثانية احتفالاً. الورقة تنقلب تلقائياً للأعلى إذا كانت الحالة قريبة من أسفل الشاشة، وتُثبَّت داخل حدود الشاشة. قوائم الفلاتر كما هي — دون مساس.
- **لمسات نظامية** — تصحيح صيغة تجاهل قواعد a11y إلى صيغة Svelte 5 (فاصلة بدل مسافة)، وحماية موضع ورقة الاختيار من الفيضان على الشاشات الضيقة.

## [0.11.0] — 2026-09-12 — السجل يتبع الإصبع، والورقة تُسحب للإغلاق

- **سحب بطاقة السجل يتبع الإصبع** — اسحبي البطاقة يساراً فتتحرك مع إصبعك لحظياً، ويظهر خلفها الزران معاً («تم التسليم» و«راجع») بدل زر واحد. نقرة على البطاقة المفتوحة تغلقها، والسحب للخلف يغلقها أيضاً. البطاقة المفتوحة تخفت قليلاً لتكون الأزرار بطلة المشهد.
- **ورقة التفاصيل تُسحب للأسفل للإغلاق** — كل نوافذ التفاصيل في التطبيق أصبحت تتبع إصبعك نحو الأسفل وتُغلق عند التجاوز، مع ارتداد مرن إذا لم تتجاوزي الحد (مثل تطبيقات الآيفون).
- **عمر العملية بالكلمات** — تفاصيل العملية تعرض «منذ ساعتين» بجانب التاريخ الكامل، فتعرفين عمر كل عملية بنظرة.
- **الباركود يظهر كرقاقة** — في تفاصيل العملية صار الباركود رقاقة بارزة بخط متقطع (منسيّة الحركة) بدل سطر عادي.
- **الجرد يحترم التطبيق الفارغ** — صفحة الجرد تعرض حالة «مخزونك فارغ» الجميلة بدل شريط بحث يتيم.

## [0.10.4] — 2026-09-12 — الموردون في كل مكان

- **حقل «المورد» صار نظاماً كاملاً** — سجّلي مورديك من الإعدادات (بطاقة «الموردون» الجديدة)، ثم يظهرون كقائمة منسدلة في فاتورة الوارد وفي نموذج إضافة الموديل — مثل قائمة شركات التوصيل تماماً. أي اسم جديد تكتبه يُسجَّل تلقائياً ليظهر في كل القوائم بعدها.
- **المورد يظهر مع البضاعة** — كل بطاقة مخزون وصفحة تفاصيل الموديل تعرض «من {اسم المورد}» مع تاريخ الاستلام، فتعرفين منين جاء كل قطعة.

## [0.10.3] — 2026-09-11 — شركاتك تظهر في الإتمام، ومحرر الرسالة يشتغل

- **فاتورة وارد (batch receiving)** — شاشة جديدة (المخزون ← FAB، أو المزيد): اسم **المورد** + رقم الفاتورة + أسطر موديلات × مقاسات بصفحة واحدة. المورد وسعره وتاريخه تُحفظ على المنتج نفسه وسجل حركاته — بعد ستة أشهر، «منين شريت هذا؟» لها جواب.
  - الموديل/المقاس الموجود يُدمج، وغيره يُنشأ — بدون بطاقات مكررة أبداً.
- **قوة المقاسات (size-run view)** — في تفاصيل كل موديل: شريط 36[2] 37[—] 38[3]… يكشف الثقوب فوراً، مع زر **استلام الناقص** الذي يفتح فاتورة وارد مملوءة بالمقاسات الفارغة واسم المورد السابق.
  - *Benefit:* مشكلة محل الأحذية الكلاسيكية — «عندي 37 و39 وكل زبونة تريد 38» — صارت مشهد تشوفينه، والعلاج بضغطة.
- **اقتراحات غزالة الذكية** — لوحة رئيسية جديدة فوق التنبيهات: موديل نفد وبيع منه قطعتان+ هالأسبوع ← **«فاضل تستلمين أكثر؟»** بزر استلام يملأ الفاتورة؛ والمخزون الراكد ← **«اعرضيها بخصم»** يقفز للبيع على البحث جاهزاً.
- **لون بالنقرة (color swatches)** — 12 دائرة لونية جاهزة (أسود/بيج/وردي/بordo/خردلي…) بدل كتابة الاسم؛ النقرة تملأ، والكتابة الحرة تبقى ممكنة. في نموذج الإضافة وفي كل سطر فاتورة.
- **تدفق الصورة أولاً** — «إضافة موديل» تفتح الكاميرا **قبل** النموذج، والصورة تركب معك كل الخطوات وتُطبَّع على كل مقاسات نفس الموديل (وزوجها JPEG صغير في قاعدة البيانات).
